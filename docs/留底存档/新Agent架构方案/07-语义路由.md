# 07 — 语义路由与 AI 决策跳转

> 权威收敛自：[`AIBase-语义化路由与AI决策跳转方案-v2.md`](../AIBase-语义化路由与AI决策跳转方案-v2.md)。  
> v1 仅作历史，勿再实施。

---

## 1. 一句话目标

废弃「工具成功必跳页」硬编码桥；以**语义路由清单**为单一事实源，派生菜单元数据与业务 `<Route>`，初始化 AIBase 时注入清单，由 AI 经 `navigate_to_page` 决策跳转；面板设置提供可关闭的「自动跳转」开关。

---

## 2. 已确认决策

| ID | 决策 |
|----|------|
| D1 | 删除旧写成功必跳桥 |
| D2 | ApiServices 工作流页内导航本期保留（独立订阅） |
| D3 | 自动跳转默认开 |
| D4 | 语义清单单一来源 |
| D5 | 开关仅全局 + userHabit（不做 PageScope 覆盖） |

---

## 3. 数据流

```text
frontend/src/routes/semanticRegistry.ts
  业务页语义（path / mode / title / description / domain / scopeGroup / …）
  + redirect
        │
        ├─→ routes/config.ts     buildAppRouteMeta（菜单）
        ├─→ routes/index.tsx     buildBusinessRoutes（element / scope）
        └─→ config/aiChat.ts     semanticRoutes → AIBase prompt + navigate_to_page
```

要点：

- 语义文件**不挂** React 组件；`mode` 表达 FormPage create/edit/view
- `resolveSemanticRoutePath(path, params, routes)` 强制对照清单白名单
- 开关仅约束 harness `navigate_to_page`；业务 `*_navigate` 仍走自身逻辑（设置文案标明）

---

## 4. 行为矩阵（autoNavigate）

| 场景 | 开关开 | 开关关 |
|------|--------|--------|
| AI 认为应跳 | 白名单通过 → 跳转 | 不跳，`disabled`，AI 说明 |
| 用户明确要求打开某页 | 跳 | 不跳并提示可开启 |
| 编造 path | `invalid_target` | 可优先 `disabled` |

写成功后若结果需在另一页呈现（带 id 的编辑/详情、跨模块里程碑）：协议要求调用 `navigate_to_page`（见 skillLoader 中导航硬约束）。

---

## 5. 与新架构的衔接

### 5.1 上下文经济

- `semanticRoutesToMarkdown`：**按当前 domain / scopeGroup 截断**；未激活域不注入
- 全量清单可留在运行时白名单校验，不必全文进 prompt

### 5.2 插件化

- `navigate_to_page` 为 harness 核心插件 Tool
- `navigationChannel` 随 Agent Context 生命周期管理，减少模块级单例（长期，对齐 P3）

### 5.3 Surface

- 跳转成功：`display.kind = status`（「已打开 xxx」）即可
- 不跳：`status` / `error` 说明原因，避免用户以为失败却无反馈

---

## 6. 非目标（保持）

- 框架布局 / 认证 / 公开文档 / 错误页不进语义清单
- 不做跳转历史 / 回退
- 不合并业务 `*_navigate` 进 `navigate_to_page`（本期）
- 不做 PageScope 级 autoNavigate 覆盖（本期）
