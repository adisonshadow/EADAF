# 06 — 闭环与终止

> 收敛自：[`AIBase 成熟闭环与 Planning next moves 统一方案.md`](../../AIBase%20成熟闭环与%20Planning%20next%20moves%20统一方案.md)。  
> Planning UI 细节见 [05-展示协议](./05-展示协议.md)；此处保留执行内核与终止语义。

---

## 1. 一句话目标

把 AIBase 从「文本驱动的自动续跑」升级为「**结构化任务驱动**的成熟闭环 Agent」：每一轮都能回答当前目标、当前步骤、是否验收通过；写操作与查询操作终止语义分离。

---

## 2. 六阶段状态机

```text
[接收] → [勘察] → [规划] → [执行] → [验收] → [交付]
   ↑                              │
   └──────── 回退 ────────────────┘
```

原则：每个阶段有明确出口条件；**不允许**靠自然语言「感觉完成」结束。

| 阶段 | 要点（业务 Agent 语境） |
|------|-------------------------|
| 接收 | 歧义用 `ask_user`；生成可验证成功标准 |
| 勘察 | 先读现状（list/get/页面 Surface），再改 |
| 规划 | `update_plan` 外部化步骤 |
| 执行 | native Tool / 可选 `run_code`；写后 verified |
| 验收 | `task_complete` 校验 plan + verified + 策略 |
| 交付 | summary + next_steps + Surface 上已展示的数据 |

业务场景的「勘察」是读模型/API/列表，不是扫代码仓库。

---

## 3. 工程落地：结构化终止

主线机制：

- `update_plan`：权威任务清单
- `task_complete`：显式终止 + 验收
- `reconcilePlan()`：按 Tool 结果对账
- `decideStructuredTermination()`：text-only round 判定 terminate / continue / hard-stop
- 收敛检测：连续相同 Tool / 错误指纹 → hard-stop

### 3.1 查询型轻量闭环

「列出所有成员」类任务：

1. 理解意图 → 极小 plan（可 1 步）
2. 调查询 Tool；失败可重试
3. 结果足够回答 → **交付即终止**
4. 不开启无意义的下一轮执行

策略开关：`allowDirectAnswerTermination`（已在部分只读 Skill 启用，需扩展到更多只读 Skill）。

### 3.2 写操作闭环

- 标记 completed 前对应 Tool 须 `verified=true`
- `task_complete` 失败返回 `TASK_INCOMPLETE` + incomplete 列表 → 继续推进，禁止口头宣称完成
- 危险写操作前优先 `ask_user`

## 4. 双机制收敛（P1）

现状：`enableStructuredTermination` 与旧 `shouldAutoContinueAfterTextOnly`（关键词）并存；SDK 内仍有中文进度/收尾正则。

目标：

1. 结构化终止为**唯一主路径**（默认 true）
2. 关键词 / 中文正则降为可配置兜底或删除出 SDK 核心
3. 主信号：`plan` 全 completed + 关键 Tool verified + successCriteria / 查询型直收尾

## 6. 状态容器（P1-3）

`agentPlanState` 模块级 holder + Hook 内大量闭包 `let` → 多会话污染风险。

目标：`TurnContext` / `TurnState` 显式传入；`update_plan` / `task_complete` 经 turnId 取状态。与 Cordis session 作用域对齐（[01](./01-插件内核.md)）。

---

## 7. 推荐推进顺序（体验侧）

1. MS0：默认 Surface（用户先能看见数据）
2. Planning 视觉与同步（过程态透明）
3. 扩展查询型直收尾 Skill
4. MS4：单一终止主路径
5. MS6：回放「为什么停 / 继续」
