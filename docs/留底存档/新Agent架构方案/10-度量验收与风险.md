# 10 — 度量、验收与风险

> 合并自：重设计方案第 8–9 章；并纳入展示 / 插件 / 代码运行时验收。

---

## 1. 北极星指标

| 指标 | 现状基线（定性） | 目标 |
|------|------------------|------|
| 单任务工具调用成功率（一次即 verified / 读成功） | 低（「经常失败」） | 关键写操作 ≥ 90%；读操作更高 |
| 因参数错误触发的失败占比 | 高（无预校验） | 下降 70%+（MS0） |
| 「有 data 但 UI 无 Surface」次数 | 常态 | → 0（默认推断后） |
| 单页 system prompt 体积 | 全文 Skill + 全量路由 | 下降 50%+（MS2） |
| 单页模型可见 Tool 数 | 可达数十 | 导向 ≤ 15（合并 + 可见性） |
| 终止误判（过早 / 不结束） | 有 | 查询直收尾 + 写闭环回归全绿 |
| 上下文压缩后「失忆」 | 有 | 压缩后仍能回答当前进度 |
| 业务包接入工时 | 需改宿主源码 | 按模板挂 pack 可跑通（MS5） |

## 2. 分里程碑验收清单

### MS0

- [ ] 非法 JSON / 缺必填：不进 handler；模型收到字段级错误
- [ ] list/get 成功：用户可见 table/entity（或 empty）
- [ ] 错误信封含 `category` / `retryable`（至少 invalid_args）

### MS1

- [ ] Cordis Context 随 Provider boot/dispose
- [ ] 现有 client Tool 行为回归通过
- [ ] 注册随 dispose 清理（无泄漏）

### MS2

- [ ] capabilities 目录化；`skill` 可加载正文
- [ ] 未激活 Skill 正文不进常驻 prompt
- [ ] 语义路由按 domain 截断

### MS3

- [ ] `run_code` JS 可调已授权 Tool；不可越权
- [ ] 超时 / 输出截断生效；Python 后端可用（若已交付）

### MS4

- [ ] bizdata（或首域）Tool 数下降且准确率不降
- [ ] 结构化终止为唯一主路径
- [ ] 多会话 plan 不互相污染

### MS5

- [ ] 独立 application 业务包联调通过

### MS6

- [x] 可回放 turn：工具、信封摘要、终止 reason（设置面板 Turn 回放）
- [x] `run_subagent` fanout/sequence 骨架（隔离子 Turn；嵌套 LLM 后续）
- [x] Tool 指标聚合 + `X-AIBase-TurnId` 透传；后端 api_request_logs 审计列

## 3. 风险与灰度

| 风险 | 缓解 |
|------|------|
| 工具合并选错 action | 先读后写；旧名别名；分域灰度 |
| Cordis 引入学习成本 | 先 adapter 包现有 API；文档 + 模板包 |
| `run_code` 安全 | 同用户 Tool 权限；禁任意 IO；审批链不绕过；审计子调用 |
| 默认 Surface 误展示敏感字段 | payload 白名单 / 字段级 redact；默认只展示 summary 列 |
| 终止收敛行为变化 | 开关灰度一个版本周期 |
| Skill 正文外迁 | 先双写再切 |
| DB 与插件 schema 认知混乱 | 文档写清权威源；启动校验告警 |

### 回滚

- 配置开关关闭新校验严格模式 / 关闭 run_code / 关闭 Cordis 新路径（回退兼容层）
- 旧 Tool 名别名保留至少一个版本
- 不强制删除旧文档与旧分支逻辑直至回归稳定

## 4. 观测最小集（MS6 前也要有）

即使完整回放面板未上，MS0 起应具备：

- turnId 贯穿一轮用户提交
- 每次 tool：name、校验成败、category、duration
- 终止：terminate / continue / hard-stop + reason 码

对齐旧 [`p2-observability.md`](../../improvements/p2-observability.md) 的 turnId / 指标方向。

---

## 5. 结语

EADAF Agent 已在信封、收敛检测、HITL、结构化终止雏形、语义路由上做对了方向。当前缺口是：**插件化扩展面、按需加载、参数契约、标准化展示、可选代码编排**。

按 MS0→MS6 推进：先让调用稳、结果看得见，再让上下文瘦、能力可组合，最后做编排与可解释性。业务系统通过插件包接入，而不是 fork 内核。
