# 05 — 展示协议（Tool Surface）

> 新增核心章节。合并 Planning next moves 体验目标。  
> **这是「必须展示的数据没展示 / 展示混乱」的主修复面。**

---

## 1. 现状根因（已修复方向）

历史上 [`ToolInvokeSteps`](../../../package/ai-base/src/ui/ToolInvokeSteps.tsx) 只渲染 ThoughtChain **状态行**，工具成功时的 `ToolResponse.data` 不进 UI；后来 MS0 补了 `display.kind`，但仍是「ThoughtChain + 下方 Surface」双轨，标题重复、技术输出默认展开。

**当前目标**：统一为 **InvocationCard**（标题栏 + 可折叠内容区），由 `ctx.surfaces` 的 presentation 清单驱动折叠/高度/内容模式；`ToolResultSurface` 仅作 **纯 body**。

Markdown 图表（GPT-Vis）与 A2UI `next_steps` 是旁路能力，**不能替代** Tool 结果的标准化卡片。

---

## 2. 目标：三轨分离 + Chrome

```text
execute → envelope
            ├─ data / verified     → 程序 / mutation / 校验
            ├─ render + agentHint  → 回灌模型（短）
            └─ display + chrome    → 用户 Surface（标准化）
```

UI **按 `display.kind` 选 body 组件**，**按 presentation 清单配置壳**，禁止按 tool 名特判折叠/高度（业务包可通过 surfaces 注册）。

---

## 3. Surface 词表

| kind | 何时必须展示 | payload 要点 |
|------|----------------|--------------|
| `table` | list / query 成功且有行 | columns + rows（或 dataSource） |
| `entity` | create / get / update 成功 | 字段字典或 schema+values |
| `metric` | 指标执行 | 标题、值、单位、对比 |
| `chart` | 工具声明或等价 vis | GPT-Vis / 图表 spec |
| `diff` | 配置 / 模型变更 | before / after |
| `approval` | 危险写确认 / 与 ask_user 对齐 | 选项 |
| `json` | 兜底 | 截断后的结构化数据 |
| `empty` | 成功但无行 | 空态文案 |
| `status` | 纯副作用（navigate / theme） | 一句话即可 |
| `planning` | 过程态计划 | items[]（标题在 chrome） |
| `error` | 业务/系统失败 | code + message + hint（可展开） |

### 3.1 协议形状

```ts
display?: {
  kind: DisplayKind
  /** 可选；标题栏由 InvocationCard 的 title/subtitle 负责，body 一般不重复 title */
  title?: string
  payload: unknown
  collapsed?: boolean
  visibility?: 'sticky' | 'transient' | 'result_hidden'
  previewLines?: number
}
```

`ChatToolStep` 携带：

- `title` / `subtitle` / `presentation` / `args` / `display`
- `displayName`：兼容复制/回放（通常 `title · subtitle`）

### 3.2 默认填充规则（内核保证）

查询 / 读成功且 `data` 非空而 handler **未**声明 `display`：

1. 数组或 `{ rows }` → 默认 `table`
2. 普通对象 → 默认 `entity`
3. 空数组 → `empty`
4. 纯副作用成功 → `status`

**不允许**「只给模型看、用户只看到一行状态」。

写成功：至少 `entity` 或 `status` + verified 标记；需要跳转时配合 `navigate_to_page`（见 [07](./07-语义路由.md)）。

## 4. ctx.surfaces（已落地）

对齐 Harness：`presentCall` / `presentResult` → chrome + display → UI。

| API | 职责 |
|-----|------|
| `registerPresentation(name, profile)` | tool/action → 壳配置清单 |
| `registerKind(kind, Component)` | `display.kind` → React 组件 |
| `presentCall(name, args)` | 标题栏 title/subtitle + presentation |
| `presentResult(name, args, envelope)` | 更新 chrome + 归一化 display |
| `registerInvocationPresentation` | 无 Cordis 时的兼容入口 |

### 4.1 InvocationPresentation（壳配置）

```ts
interface InvocationPresentation {
  category: 'technical' | 'business'
  icon: 'skill' | 'http' | 'code' | 'plan' | 'table' | 'write' | 'nav' | 'generic'
  title: string                      // 静态动词：加载 Skill
  contentMode: 'in_out' | 'name_output' | 'request_response'
  collapseDuring: boolean
  collapseAfter: boolean
  collapsedPreviewLines: number      // 0 = 全收；>0 留 N 行（同一份内容裁切，不另渲截断 JSON）
  maxHeight: number
}
```

默认策略：

- `technical`（skill / run_code / http / subagent / navigate）：执行中/后折叠，`collapsedPreviewLines: 0`
- `business`：结束后展开；`visibility: transient` 时下一步开始按 presentation 收起

内容模式：

| 模式 | 展示 |
|------|------|
| `in_out` | IN（args/代码）+ OUT |
| `name_output` | 标题栏已有名，内容区仅 OUT |
| `request_response` | 请求行 + 响应 |

### 4.2 InvocationCard 交互

1. 标题栏：icon + 标题 + 副标题（例：`加载 Skill · 业务数据模型设计`）
2. 执行中：标题扫光；结束后 icon 显示成功/失败（business_error 蓝 / system_error 红）
3. 悬停标题栏：icon 槽切为展开/折叠 chevron；点击切换内容区
4. 耗时放 tooltip，不再当副标题

落点：[`InvocationCard.tsx`](../../../package/ai-base/src/ui/invocation/InvocationCard.tsx)、[`surfacesRegistry.ts`](../../../package/ai-base/src/runtime/surfacesRegistry.ts)、[`SurfacesService`](../../../package/ai-base/src/runtime/surfacesService.ts)。

业务包：

```ts
ctx.surfaces.registerPresentation('acme_list_orders', { title: '列出订单', category: 'business', icon: 'table' })
ctx.surfaces.registerKind('acme_order_table', AcmeOrderTable)
```

## 5. Planning next moves

来自成熟闭环文档的体验目标，并入 Surface：

### 5.1 已有基础

- `update_plan` / `reconcilePlan`
- `assistantSegments` 已有 `planning` 类型
- 部分路径已能渲染（经 markdown 转换）

### 5.2 目标体验

```text
Planning next moves
- 重试查询成员列表        (in_progress)
- 校验返回结果是否完整    (pending)
```

触发：首次 `update_plan`、每轮对账后、自动重试前。

原则（与实测1对齐）：

- **短暂过程态**：出现后，一旦下一条**非 harness** 业务 Tool 开始执行，或本轮文本交付 / 终止，从当前消息 segments **移除**，不必常驻给用户看
- 权威任务清单仍以 `update_plan` 的 Tool Surface（`display.kind=planning`）为准，不另做第二套永久任务板
- 只显示 1–3 条最相关步骤；查询型最多极简计划
- 不替代最终答案；不泄露系统提示词
- UI 用 `kind: 'planning'` 轻量条；可与 Tool Surface 并存但过程态可隐藏

## 6. A2UI next_steps 与其它旁路

| 机制 | 用途 | 与 Surface 关系 |
|------|------|-----------------|
| A2UI `next_steps` | 阶段完成后的可选动作按钮 | 保留；属交付层，不是 Tool 结果卡 |
| `ask_user` ChoiceCard | mid-task HITL | 可视为 `approval` 族；**不**塞进 InvocationCard |
| GPT-Vis 代码块 | 模型在 Markdown 里画图 | 可与 `chart` Surface 并存；Tool 有数据时优先 Tool `chart`/`table` |

---

## 7. 模型侧约束（prompt）

在执行协议中补充硬约束（摘要）：

- 列表 / 详情类 Tool 成功后，用户界面会展示结构化结果；**禁止**用大段重复粘贴同一表格到 Markdown（除非用户要求导出）
- 需要图表时优先让 Tool 返回 `display.kind=chart`，或使用约定的 vis 块
- 失败时向用户说明 `error.message`，不要假装成功
